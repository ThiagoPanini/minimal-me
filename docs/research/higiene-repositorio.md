### CODEOWNERS

- Documentação: <https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners>. O arquivo `CODEOWNERS` pode ficar em `.github/`, na raiz ou em `docs/`; havendo mais de um, o GitHub usa o primeiro nessa ordem. Vale por branch: precisa estar na branch base do PR. Os owners são solicitados automaticamente como revisores dos PRs que tocam seus caminhos (em draft, só quando marcado como pronto). A exigência de aprovação deles é a opção "Require review from Code Owners" em branch protection, ou o parâmetro equivalente em rulesets (`require_code_owner_review`). Owners individuais e equipes precisam de acesso de escrita; equipes precisam estar visíveis. Sintaxe: padrões no estilo gitignore seguidos de `@usuario`, `@org/equipe` ou e-mail; `!`, intervalos `[ ]` e escape de `#` não funcionam; linhas inválidas são ignoradas; limite de 3 MB.
- Observado: nenhum dos 18 caminhos (`CODEOWNERS`, `.github/CODEOWNERS`, `docs/CODEOWNERS` × 6 repos) existe (`gh api repos/<r>/contents/<caminho>` → 404). Todos os seis rulesets têm `require_code_owner_review: false` e `required_approving_review_count: 0` (`gh api repos/<r>/rulesets/<id>`); a nota em `panlabs-tech/.github/config/ruleset.json` registra o motivo: o autor não pode aprovar o próprio PR, e exigir revisão travaria o merge autônomo. `ThiagoPanini` é conta de usuário (`gh api user --jq .type` → `User`), sem equipes.
